# Технический радар «Будущее 2.0»

Радар классифицирует технологии и паттерны по двум осям: квадранты (вид) и кольца
(стадия внедрения). Кольца: **Adopt** — берём в прод, **Trial** — проверяем на
пилоте, **Assess** — изучаем прототипом, **Hold** — не используем в новом и
выводим.

Квадранты адаптированы под компанию, у которой ядро — данные и ИИ.

## Языки и фреймворки

| Технология | Кольцо | Обоснование |
|---|---|---|
| Go | Adopt | сервисы доменов: клиники, финтех, снабжение |
| Python | Adopt | инференс и обучение ИИ-моделей |
| React + TypeScript | Adopt | портал самообслуживания и веб-АРМ |
| Java | Trial | финтех-модули остаются, новые сервисы переезжают на Go |
| Rust | Assess | смотрим для горячих мест инференса и парсинга |
| PowerBuilder | Hold | интерфейс операторов заменяется веб-АРМ |

## Методы и паттерны

| Паттерн | Кольцо | Обоснование |
|---|---|---|
| Data Mesh | Adopt | целевой подход: домены владеют данными |
| Event-Driven Architecture | Adopt | события вместо синхронных интеграций и DWH |
| Self-service BI | Adopt | отчёты без заявки в ИТ |
| Domain-Driven Design | Adopt | границы доменов и контракты |
| CI/CD | Adopt | автоматизация выкладки и проверки схем |
| CQRS | Assess | разделение чтения/записи в горячих местах |
| Event Sourcing | Assess | полная история там, где нужен аудит |

## Как радар живёт

Пересматриваем раз в полгода. Движение между кольцами — только через ADR:
фиксируем проблему, решение и критерии перехода. Драйвер перехода — инженер,
который отвечает за технологию.
