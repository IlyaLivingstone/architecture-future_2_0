# Агрегаты

Агрегат — граница согласованности внутри контекста: одна транзакция меняет ровно
один агрегат. Между агрегатами и контекстами согласованность итоговая, через
события.

Ниже — агрегаты по контекстам: границы, инварианты, ключ и что агрегат публикует.

## Клиники

### Пациент (контекст «Пациенты и визиты»)

- **Границы:** профиль пациента, контакты, согласия на обработку данных.
- **Инварианты:** у пациента один идентификатор на всю сеть; визит нельзя открыть,
  если нет обязательных согласий; согласие можно отозвать, но не удалить факт.
- **Ключ:** `patientId`.
- **Публикует:** `ПациентЗарегистрирован`, `СогласиеОбновлено`.

### Визит (контекст «Пациенты и визиты»)

- **Границы:** пациент, клиника, время, набор оказанных услуг, статус визита.
- **Инварианты:** визит принадлежит одному пациенту и одной клинике; услугу нельзя
  добавить в закрытый визит; сумма по визиту считается по оказанным услугам и не
  редактируется вручную; статус меняется только вперёд (открыт → завершён).
- **Ключ:** `visitId`.
- **Публикует:** `ВизитОткрыт`, `УслугаОказана`, `ВизитЗавершён`.

### МедицинскаяЗапись (контекст «Медицинские записи»)

- **Границы:** содержимое ЭМК по визиту, назначения, заключения, привязка к
  исследованиям.
- **Инварианты:** запись привязана к визиту и пациенту; после закрытия содержимое
  не меняется, правки идут отдельной записью; содержимое не покидает контекст —
  наружу уходят только факты.
- **Ключ:** `recordId`.
- **Публикует:** `МедЗаписьСоздана`, `МедЗаписьЗакрыта`.
- **Потребляет:** `ВизитОткрыт`, `ВизитЗавершён`, `СогласиеОбновлено`, `ИИАнализЗавершён`.

## ИИ-сервисы

### ИИАнализ (контекст «ИИ-диагностика»)

- **Границы:** запрос на инференс, входные данные исследования, использованная
  версия модели, класс результата.
- **Инварианты:** один анализ на один запрос; результат неизменяем, повторный
  прогон создаёт новый анализ; класс результата не подменяется задним числом.
- **Ключ:** `analysisId`.
- **Публикует:** `ИИАнализЗапрошен`, `ИИАнализЗавершён`.
- **Потребляет:** `МедЗаписьСоздана`, `МодельЗарегистрирована`, `ДанныеОборудованияПолучены`.

### Модель (контекст «ML-платформа»)

- **Границы:** версия модели, назначение, метрики качества, признаки.
- **Инварианты:** версия после публикации неизменяема; новая версия — новый
  идентификатор; снятую версию нельзя вернуть в инференс без новой публикации.
- **Ключ:** `modelId` + `version`.
- **Публикует:** `МодельЗарегистрирована`, `МодельВыведенаИзЭксплуатации`.

## Финтех

### Счёт (контекст «Платежи и счета»)

- **Границы:** счёт по завершённому визиту: сумма, срок, статус оплаты.
- **Инварианты:** сумма счёта больше нуля; счёт нельзя выставить дважды по одному
  визиту; статус меняется только вперёд (выставлен → оплачен).
- **Ключ:** `invoiceId`.
- **Публикует:** `СчётВыставлен`.
- **Потребляет:** `ВизитЗавершён`, `УслугаОказана`, `КредитныйДоговорСоздан`.

### Платёж (контекст «Платежи и счета»)

- **Границы:** поступивший платёж, ссылка на счёт, канал и сумма.
- **Инварианты:** платёж идемпотентен по `paymentId`; повторный платёж по тому же
  счёту не задваивает выручку; сумма платежа не превышает остаток по счёту.
- **Ключ:** `paymentId`.
- **Публикует:** `ПлатёжПолучен`.

### КредитныйДоговор (контекст «Кредитование»)

- **Границы:** заявка, решение, сумма, срок, график платежей, статус.
- **Инварианты:** график покрывает всю сумму; сумма платежей равна сумме договора;
  договор нельзя закрыть, пока есть непогашенные платежи; изменение графика — новая
  версия договора.
- **Ключ:** `contractId`.
- **Публикует:** `ЗаявкаНаКредитПодана`, `КредитныйДоговорСоздан`, `ПлатёжПоГрафикуПолучен`.
- **Потребляет:** `СчётВыставлен`, `ПлатёжПолучен`.

## Головной офис

### Сотрудник (контекст «Персонал»)

- **Границы:** карточка сотрудника, роли, назначение на клинику, интервалы
  действия роли.
- **Инварианты:** роль действует в заданном интервале; сотрудник не может иметь
  две активные роли одного типа в одну смену.
- **Ключ:** `employeeId`.
- **Публикует:** `СотрудникПринят`, `НазначениеИзменено`.

### Закупка (контекст «Снабжение»)

- **Границы:** поставщик, строки закупки, сумма, статус приёмки.
- **Инварианты:** сумма закупки равна сумме строк; принять можно не больше
  заказанного; приёмка по строке необратима.
- **Ключ:** `purchaseId`.
- **Публикует:** `ЗакупкаОформлена`, `ТоварПринят`.

### ОтчётныйПериод (контекст «Финотчётность»)

- **Границы:** read model — сводка по событиям доменов за период.
- **Инварианты:** сводка строится только из подтверждённых событий; после закрытия
  периода пересчёт не меняет опубликованный отчёт, а добавляет корректировку.
- **Ключ:** `periodId`.
- **Публикует:** `ОтчётСформирован`.
- **Потребляет:** события визитов, исследований, платежей, договоров и закупок.
