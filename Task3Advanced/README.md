## Что меняется

| Что | Сейчас | Цель |
|---|---|---|
| Ядро | один DWH, в нём же бизнес-логика | домены со своими сервисами и хранилищами |
| Обмен между системами | синхронные вызовы через Camel и общие таблицы | версионированные события через Kafka |
| Отчёт | аналитик делает выборку по заявке, ждём часы | сотрудник сам собирает в портале |
| Рабочее место врача | старый клиент PowerBuilder | веб-АРМ |
| Медданные | лежат в общем хранилище | остаются в клиническом домене, в аналитике их нет |
| Новый бизнес | новые маршруты и хранимые процедуры | контракт событий, ядро не трогаем |
| Железо | свои серверы | облако + Terraform |
| Загрузка данных | пакетами ночью | по мере появления (CDC) |

## Ключевые решения

- Домены публикуют события только через шину и не пишут напрямую в чужие базы.
  Подключение нового потребителя не трогает издателя.
- Контракты версионируются через каталог схем, невалидные сообщения уходят
  в DLQ.
- Медкарты, истории болезни и результаты исследований остаются в клиническом
  домене. В аналитику идут только обезличенные факты — код услуги, длительность,
  класс результата ИИ. Фильтр стоит в контейнере приёма, до Lakehouse.
- Портал не ходит в домены напрямую: только семантический слой и каталог, доступ
  проверяется на каждый запрос.
- DWH и Camel оставлены как мосты совместимости и уходят из критического пути
  к концу третьего года.
